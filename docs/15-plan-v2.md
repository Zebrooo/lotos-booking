# План v2: реализация дизайна «Лотос v2»

Источник: `design/v2/` — прототипы «Запись (клиент)», «CRM» и «Варианты экранов»,
тема `lotos-soft.css`. Реализуем вариант «a» каждого экрана — тот, что в
прототипах. Задача от Дмитрия 25 сентября 2026: всё по дизайну v2, пиксель в
пиксель, весь функционал.

## Что дизайн меняет в продукте

| Было в v1 | В дизайне v2 | Решение |
|---|---|---|
| На сайте только оплата сразу | Выбор: оплатить онлайн или забронировать и оплатить до 17:00 (переключатель `payModel`: обе / только онлайн / только бронь) | Реализуем все три режима настройкой `settings.pay_model`, по умолчанию «обе», как в прототипе. **Противоречит договорённости 15 сентября** — нужно подтверждение директора. |
| Почта для чеков и писем | Телефон и СМС: код подтверждения, ссылка на оплату, чек, напоминание; почта — по желанию в кабинете | Порт `SmsSender` с заглушкой в лог; чеки на телефон, на почту — если указана в кабинете |
| Запись без проверки телефона | Код из СМС перед оплатой или бронью | Таблица кодов, 4 цифры, 5 попыток, повтор через 60 с |
| Записать родственника | «Другой взрослый»: согласие даёт сам по ссылке из СМС, запись подтвердится после согласия | Отдельная страница согласия по токену; без согласия запись не подтверждается |
| — | Приём «при наборе группы»: минимум записей и срок решения | Таблица групповых дней; метка в поиске, точка в календаре, блок на странице врача, метка в CRM |
| — | Личный кабинет по номеру телефона: записи, документы, платежи, профиль, семья | Вход по коду из СМС, сессия в cookie; данные — по пациентам с этим телефоном |
| — | Документы: заключения, анализы, исследования | Таблица документов и отметок о прочтении. Откуда они берутся, дизайн не показывает: наполнение из 1С и лаборатории — после сеанса AnyDesk, для показа — демо-данные |
| — | Справка для налогового вычета, заявка на добавление ребёнка | Заявки сохраняются; в CRM дизайн их не показывает |
| Кабинет администратора v1 | CRM: расписание сеткой, записи, сверка оплат, печать на завтра, роль врача, снятие приёма, пауза | Полностью по дизайну. Переключатель ролей «для прототипа» заменяется входом сотрудника: роль берётся из учётной записи |
| — | Сверка оплат: поступления из банка по СМС | Таблица поступлений и ручное сопоставление; источник поступлений — точка приёма для пересылки СМС банка, в дизайне её нет |
| — | Квота сайта в расписании | Таблица интервалов квоты, в CRM — штрихованные зоны |

## Чего в дизайне нет, а без этого не работает

- Вход сотрудников в CRM: страница входа в той же теме.
- Страница согласия взрослого пациента по ссылке из СМС.
- Создание записи по телефону в CRM: в дизайне нет. Записи «Телефон» и «Стойка» появятся после обмена с 1С; пока — демо-данные.
- Кнопка «Я оплатил» у пациента: в CRM есть состояние «Оплата заявлена», в клиенте кнопки нет. Состояние поддерживаем, источник — отметка администратора.

## Этапы

1. **Основа.** Тема `lotos-soft.css` и шрифт Onest без Tailwind; шапка, подвал, степпер; миграция схемы v2; демо-клиника из прототипа: 12 врачей, услуги, стаж, кабинеты, групповой день, квота.
2. **Домен v2.** Статусы `pending`, `claimed`, `arrived`; срок брони «самое раннее из: ближайшие 17:00 не раньше чем через час, за 2 часа до приёма»; маски и проверки формы как в прототипе; коды СМС.
3. **Запись пациента.** Поиск с фильтром специальностей, страница врача с лентой дней и календарём, форма «Кто придёт», выбор оплаты, код из СМС, страница банка, «Готово», «Моя запись» с отменой и переносом.
4. **Личный кабинет.** Вход, обзор, записи, документы с окнами, платежи и справка, профиль и семья, окно записи.
5. **CRM.** Вход, расписание, карточка записи с журналом и действиями, список, сверка, печать, приём врача и запрос, пауза, снятие приёма.
6. **Фон.** Истечение брони, согласия и удержаний, напоминания и чеки по СМС.
7. **Сверка с дизайном.** Скриншоты прототипа и реализации рядом на 1280 и 390 пикселей по каждому экрану.

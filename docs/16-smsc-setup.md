# Подключение SMSC и регистрация IP

## 1. Что сделать в кабинете SMSC

1. Зарегистрировать аккаунт на юридическое лицо клиники и пополнить баланс.
2. В разделе «Отправители» зарегистрировать `LOTOS` и дождаться согласования.
3. Согласовать авторизационный шаблон с назначением кода и названием сайта, например: `Лотос: код для входа в личный кабинет — %d. Никому его не сообщайте.`
4. Согласовать сервисные шаблоны подтверждения, напоминания, переноса и отмены записи. Не добавлять рекламу, диагнозы, исследования и специальность врача.
5. Создать отдельный API-ключ для production. Не использовать основной пароль аккаунта и не публиковать ключ в репозитории.
6. В настройках API/IP добавить **публичный исходящий IPv4 production-сервера** в список разрешённых. Если включён SMPP, разрешённые IP указываются на странице SMPP: https://smsc.ru/api/smpp/. Для HTTP API ошибка `error_code=2` может означать неверный ключ или неразрешённый IP; статус доставки `239` — запрещённый IP: https://smsc.ru/api/http/status_messages/errors/.

Домашний IP не нужен. Если хостинг меняет исходящий адрес, нужен постоянный адрес или статический NAT/egress. Нельзя открывать отправку со всех адресов ради устранения ошибки.

## 2. Переменные production

```dotenv
SMS_PROVIDER=smsc
SMSC_API_KEY=секретный-api-ключ
SMSC_SENDER=LOTOS
SMS_CODE_PEPPER=длинная-случайная-строка
SITE_URL=https://запись.домен-клиники.ru
```

Локально остаётся `SMS_PROVIDER=log`, код читается в серверном логе `[смс:лог]`. Production с `SMS_PROVIDER=log` намеренно не запускается.

## 3. Проверка без утечки секретов

После настройки IP и шаблонов:

1. Перезапустить приложение с production-окружением.
2. Открыть `/kabinet`, ввести номер существующего тестового пациента.
3. Проверить получение SMS на реальном телефоне и вход по коду.
4. Проверить ошибочный код, истечение кода, повтор через 60 секунд и лимит пяти кодов в час.
5. Проверить статус в кабинете SMSC. Коды и полные телефоны в логах приложения быть не должны.

Ошибки: `2` — ключ или IP; `239` в статусе — IP; `254` — имя отправителя; `238` — шаблон; `224` — баланс. Сетевая ошибка и таймаут возвращаются пользователю как «Не удалось отправить СМС». Безопасная причина без телефона и кода пишется в серверный лог `[смс]`, а для фоновых уведомлений — также в `last_error` очереди.

Реальная отправка не выполняется автоматическими тестами: тесты используют имитацию HTTPS-ответов и не расходуют баланс.

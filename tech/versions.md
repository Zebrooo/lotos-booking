# Версии пакетов

Проверено 14 сентября 2026 года. Результат аудита: **ноль уязвимостей** на 678
пакетов в дереве зависимостей. Полный отчёт — `audit.json`.

## Поправки 15 сентября 2026, первая установка

Проверено установкой и прогоном линта, типов, тестов и сборки, а не только
аудитом дерева зависимостей.

- **ESLint 9.39.5 вместо 10.10.0.** `eslint-config-next` 16.3.5 тянет
  `eslint-plugin-react` 7.37, который зовёт `context.getFilename`; в ESLint 10
  этого метода нет, линт падает на первом же файле. Диапазон
  `eslint-config-next` — `>=9`, линия 9 работает.
- **TypeScript 5.9.3 вместо 7.0.2**, как и предлагалось ниже: рисковать
  совместимостью инструментов на старте незачем.
- **Убраны** `drizzle-orm`, `drizzle-kit`, `luxon`, `@types/luxon`, `undici`,
  `@vitejs/plugin-react`, `@testing-library/*`, `jsdom`: по дизайну v1
  (`../docs/12-design-v1.md`) запросы — сырой SQL, время — фиксированное
  смещение, компонентных тестов в первой части плана нет.
- `pnpm.overrides` из `package.json` переехал в `pnpm-workspace.yaml`: pnpm
  10.28 поле в `package.json` больше не читает.
- Для Tailwind 4 нужен `postcss.config.mjs` с `@tailwindcss/postcss`; в
  прежнем списке его не было.

## Как проверялось

```bash
npm install --package-lock-only
npm audit --json
```

Версии взяты из реестра npm на дату проверки, не по памяти. Аудит прогонялся на
собранном дереве зависимостей, а не на списке прямых пакетов.

## Найденная уязвимость и как она устранена

Первый прогон дал четыре уязвимости средней тяжести, все в одной цепочке:

```
drizzle-kit 0.31.10
  └─ @esbuild-kit/esm-loader
       └─ @esbuild-kit/core-utils
            └─ esbuild 0.18.20   ← GHSA-67mh-4wv8-2f99
```

`@esbuild-kit/*` — заброшенные пакеты, влитые в `tsx`, они жёстко тянут esbuild
0.18. Уязвимость позволяет любому сайту слать запросы к dev-серверу esbuild и
читать ответы. Затронуты версии до 0.24.2 включительно.

Автоматическое предложение npm — откатить `drizzle-kit` до 0.18.1 с потерей
мажорной версии. Это негодный путь.

**Принятое решение** — переопределение версии esbuild во всём дереве:

```json
"pnpm": { "overrides": { "esbuild": "^0.25.0" } },
"overrides": { "esbuild": "^0.25.0" }
```

Два ключа нужны, потому что `overrides` читает npm, а `pnpm.overrides` — pnpm.
Проект использует pnpm, но аудит удобнее гонять через npm.

Практический риск был невелик: `drizzle-kit` применяет esbuild только для
транспиляции конфигурационного файла и dev-сервер не поднимает. Тем не менее
переопределение стоит одной строки и убирает находку из отчётов.

**Проверенная альтернатива:** отказаться от `drizzle-kit` вовсе. Миграции в
проекте всё равно пишутся сырым SQL по конвенции команды, а `drizzle-orm` в
рантайме этой цепочки не тянет. Аудит в этом варианте тоже чистый. Оставили
`drizzle-kit` ради сверки схемы, но выбросить его можно в любой момент.

## На что обратить внимание

**TypeScript 7.** На npm это `latest`: линия 5.x закончилась на 5.9.3, версия 6.0
дальше беты не вышла. TypeScript 7 — переписанный на Go компилятор, и часть
стороннего инструментария может его ещё не поддерживать. Консервативная замена —
`typescript@5.9.3`, она снимает риск ценой отказа от нового компилятора. Решение
принять при первой сборке, а не сейчас.

**Версии пинуются точно, без `^`.** В проекте, где идут платежи и персональные
данные, воспроизводимость сборки важнее автоматических обновлений. Обновлять
осознанно, прогоняя аудит.

**Аудит гонять в непрерывной интеграции.** `pnpm audit --audit-level=low` в
отдельном шаге. Чистый отчёт на сегодня не означает чистый через месяц.

**Версии Next и eslint-config-next держать одинаковыми.** Сейчас обе 16.3.5.
Расхождение даёт неочевидные ошибки линтера.
